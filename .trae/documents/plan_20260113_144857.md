## 问题分析

1. **核心问题**：新建文件刷新后消失，是因为文件路径计算和父节点关系维护存在缺陷
2. **根本原因**：
   - `computedParentPath`函数依赖父节点关系构建路径，而非直接使用文件的`path`属性
   - `loadFileTree`重新构建文件树时，新文件的父节点关系可能未正确建立
   - 文件创建流程中存在路径设置不一致的问题

## 修复方案

### 1. 修复`computedParentPath`函数
- **文件**：`src/lib/path.ts`
- **问题**：函数依赖父节点关系构建路径，不够可靠
- **修复**：优先使用文件自身的`path`属性，仅在路径不存在时才通过父节点计算

### 2. 修复`file-item.tsx`中的路径处理
- **文件**：`src/app/core/article/file/file-item.tsx`
- **问题**：处理新文件命名时，路径设置逻辑有误
- **修复**：确保新文件的`path`属性正确设置，包含完整路径

### 3. 修复`loadFileTree`中的父节点关系
- **文件**：`src/stores/article.ts`
- **问题**：重新构建文件树时，父节点关系可能未正确建立
- **修复**：确保每个文件的`parent`属性正确指向其父文件夹

### 4. 修复代码位置和内容

#### 修复1：`src/lib/path.ts`
```typescript
// 修改computedParentPath函数
export function computedParentPath(item: DirTree) {
  // 优先使用item自身的path属性，如果存在则直接返回
  if (item.path && item.path !== '') {
    return item.path;
  }
  
  // 否则通过父节点计算路径
  let path = item.name
  function readParentPath(item: DirTree) {
    if (item.parent) {
      path = item.parent.name + '/' + path
      if (item.parent.parent) {
        readParentPath(item.parent)
      }
    }
  }
  readParentPath(item)
  return path
}
```
