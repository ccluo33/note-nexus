# 修复FastDFS上传失败问题

## 问题分析
1. **当前上传流程**：
   - 前端已有完整FastDFS配置（Tracker地址、端口、HTTP访问地址、存储组名、存储路径前缀）
   - 但调用后端API时只传递了http_url参数
   - 后端缺少其他关键配置，导致无法正确连接FastDFS服务器

2. **错误原因**：
   - 前后端配置传递不完整
   - 后端使用固定client.conf，无法动态获取前端配置
   - 无法正确初始化Fdfs_client进行上传

## 修复计划

### 1. 前端修改
   - 修改`src/lib/imageHosting/fastdfs.ts`中的上传调用
   - 发送完整FastDFS配置到后端：
     - trackerServer（Tracker服务器地址）
     - port（Tracker端口）
     - httpUrl（HTTP访问地址）
     - groupName（存储组名）
     - storagePath（存储路径前缀）

### 2. 后端修改
   - 修改`backend/app/api/v1/endpoints/fastdfs.py`
   - 接收完整FastDFS配置参数
   - 动态生成临时client.conf文件
   - 使用该配置初始化Fdfs_client
   - 实现基于client库的上传逻辑

### 3. 核心实现
   - **前端发送完整配置**：
     ```typescript
     const result = await invoke<any>('fastdfs_upload', {
       file,
       config: {
         trackerServer: config.trackerServer,
         port: config.port,
         httpUrl: config.httpUrl,
         groupName: config.groupName,
         storagePath: config.storagePath
       }
     });
     ```
   - **后端动态生成client.conf**：
     ```python
     # 动态生成client.conf
     temp_conf_path = f"{temp_dir}/client_{uuid.uuid4()}.conf"
     with open(temp_conf_path, 'w') as f:
         f.write(f"connect_timeout=30\n")
         f.write(f"network_timeout=60\n")
         f.write(f"charset=UTF-8\n")
         f.write(f"http.tracker_server_port=80\n")
         f.write(f"tracker_server={tracker_server}:{port}\n")
         f.write(f"group_name={group_name}\n")
         f.write(f"base_path=./tmp\n")
     ```
   - **使用client库上传**：
     ```python
     client = Fdfs_client(temp_conf_path)
     result = client.upload_by_filename(temp_file_path)
     file_id = result["Remote file_id"].decode() if isinstance(result["Remote file_id"], bytes) else result["Remote file_id"]
     ```

### 4. 验证与测试
   - 验证前端完整配置传递
   - 验证后端动态配置生成
   - 验证Fdfs_client初始化
   - 验证文件上传流程
   - 验证返回URL格式

## 预期效果
- 前端发送完整FastDFS配置到后端
- 后端使用正确配置初始化FastDFS客户端
- 成功上传文件到FastDFS服务器
