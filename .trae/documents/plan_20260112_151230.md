# 修复向量维度不匹配问题

## 问题分析

从后端日志中可以看到明确的错误信息：
```
InvalidArgumentError: Collection expecting embedding with dimension of 5, got 1024
```

**问题原因**：
1. 之前的测试中使用了简化的5维测试向量
2. 实际AI模型返回的向量维度是1024
3. ChromaDB要求同一集合中的所有向量必须具有相同的维度
4. 当插入不同维度的向量时，就会触发这个错误

## 修复方案

### 方案1：清除现有ChromaDB数据（推荐）
- 删除现有的ChromaDB数据目录
- 重新创建集合，使用实际的向量维度
- 适用于开发环境，数据不重要的情况

### 方案2：修改ChromaDB服务代码
- 添加向量维度验证
- 在创建集合时明确指定向量维度
- 处理不同维度向量的情况

## 实现步骤

### 步骤1：停止后端服务
- 停止当前运行的后端服务

### 步骤2：清除ChromaDB数据
- 删除`backend/chromadb_data`目录
- 这将删除所有现有向量数据，重新创建集合

### 步骤3：修改ChromaDB服务代码
- 在`chromadb_service.py`中添加向量维度处理
- 确保集合创建时使用正确的向量维度

### 步骤4：重启后端服务
- 重新启动后端服务
- 新的集合将使用第一个插入的向量维度

### 步骤5：测试向量上传
- 使用实际的AI向量测试上传功能
- 验证相似文档查询功能

## 预期效果

- 向量存储API不再返回500错误
- 能够正常处理1024维的实际向量
- 相似文档查询功能正常工作
- 保持与现有功能的兼容性

## 风险评估

- **数据丢失风险**：清除ChromaDB数据会删除所有现有向量数据
- **兼容性风险**：修改后的代码需要与现有前端代码兼容

## 修复的文件

- `backend/app/services/chromadb_service.py`：修改向量维度处理
- 可能需要删除`backend/chromadb_data`目录
