## 修复计划

### 1. 修复浏览器环境下的网页爬取
- **文件**：`src/lib/browser-adapter/core.ts`
- **功能**：使用可靠的CORS代理服务，解决"Failed to fetch"错误
- **实现步骤**：
  1. 使用更稳定的CORS代理服务 `https://corsproxy.io/`
  2. 优化代理请求配置，添加适当的超时和错误处理
  3. 确保代理服务能正确返回网页内容

### 2. 添加网页内容总结功能
- **文件**：`src/lib/ai.ts`
- **功能**：实现浏览器环境下的AI总结功能
- **实现步骤**：
  1. 添加 `summarizeWebContent` 函数，用于总结网页内容
  2. 使用当前配置的对话模型（primaryModel）进行总结
  3. 准备适合总结网页内容的提示词
  4. 确保AI调用在浏览器环境中正常工作

### 3. 修改链接保存逻辑
- **文件**：`src/app/core/record/mark/control-link.tsx`
- **功能**：在保存链接时，先爬取网页内容，然后调用AI模型总结
- **实现步骤**：
  1. 在 `handleSuccess` 函数中，爬取网页内容后调用AI总结
  2. 使用 `useSettingStore` 获取当前配置的对话模型
  3. 将原始内容和总结内容保存到数据库
  4. 优化加载状态显示，提升用户体验

### 4. 增强错误处理
- **文件**：`src/app/core/record/mark/control-link.tsx`
- **功能**：添加详细的错误处理和日志
- **实现步骤**：
  1. 处理爬取失败的情况
  2. 处理AI总结失败的情况
  3. 确保即使某个步骤失败，也能保存链接的基本信息
  4. 添加用户友好的错误提示

### 5. 测试和验证
- **功能**：确保网页版服务能正常工作
- **测试步骤**：
  1. 测试链接爬取功能，确保能正确获取网页内容
  2. 测试AI总结功能，确保能生成准确的总结
  3. 测试模型配置更改，确保总结模型随之更新
  4. 测试不同类型的网页，确保兼容性

## 预期效果
- 当用户输入链接并保存时，系统会：
  1. 使用CORS代理爬取网页内容
  2. 调用当前配置的对话模型总结内容
  3. 将链接、原始内容和总结内容保存到数据库
- 支持模型配置更改，总结模型会随之更新
- 解决"Failed to fetch"错误
- 提供良好的用户体验，显示合适的加载状态
